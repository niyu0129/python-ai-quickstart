## 三、卡住时的判断流程 ⚠️

```
遇到报错 / 卡住
      │
      ▼
读报错最后一行
      │
      ├─ 看懂了吗？
      │     │
      │     ├─ 懂 ──▶ 改代码，继续
      │     │
      │     └─ 不懂
      │           │
      │           ▼
      │     查「报错急救手册」38 条
      │           │
      │           ├─ 找到 ──▶ 照做
      │           │
      │           └─ 没找到
      │                 │
      │                 ▼
      │           把完整报错贴给 AI 问
      │                 │
      │                 ▼
      │           还是不行？
      │                 │
      │                 ▼
      │           写 10 行最小复现
      │           （多数时候写到一半
      │            就发现问题了）
      │
      └─ 总共超过 30 分钟了？
            │
            ├─ 否 ──▶ 继续排查
            │
            └─ 是 ──▶ 先跳过，标记下来
                      继续往下学
                      （有些问题学到
                        后面自然就懂了）
```

## 四、每天的固定流程（日循环）

```
早上 10 分钟
  └─▶ 看今天的卡片，明确目标
        │
        ▼

  └─▶ 翻 10 张背诵卡

  └─▶ 1. 打开教程，通读一遍

        │
        ▼
睡前 5 分钟
  └─▶ 打勾 + 写一行"最卡的地方"
        │
        ▼
第二天开工
  └─▶ 先解决昨天最卡的地方
```

## 六、三条决策线

**决策 1：时间不够怎么办？**

```
每天可投入时间？
      │
      ├─ 3 小时以上 ──▶ 按标准 14 天走
      │
      ├─ 1-2 小时 ────▶ 拉成 3 周
      │                只保 6/8/9/10 天精学
      │                4/5 天只看不练
      │
      └─ 不到 1 小时 ─▶ 只做第 6、9 天
                       先做出一个能用的 RAG
                       其他后面补
```

**决策 2：要不要学数学？**

```
现在能被「导数和矩阵」卡住吗？
      │
      ├─ 没有卡住 ──▶ 先不学，继续做项目
      │
      └─ 卡住了 ────▶ 只补当前用到的那一点
                       （比如只补矩阵乘法）
```

**决策 3：要不要上框架（LangChain）？**

```
你能用原生 SDK 手写出来吗？
      │
      ├─ 不能 ──▶ 先别碰框架
      │           框架会遮蔽原理
      │           出问题完全懵
      │
      └─ 能 ────▶ 可以用框架提效
                  但仍要知道它在做什么
```
