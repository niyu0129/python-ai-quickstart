# 🔧 AI 应用开发流程表（手机版）

> 从"有个想法"到"能给别人用"的完整流程。
> 每个流程都标了**哪一步最容易出问题**。

---

## 一、通用开发流程（8 步）

```
① 需求拆解
   把业务问题拆成模型能完成的小任务
   ⚠️ 最容易跳过，也最影响成败
        │
        ▼
② 选方案
   提示词能解决？→ 直接调模型
   需要私有知识？→ 加 RAG
   需要多步操作？→ 加 Agent
   ⚠️ 别一上来就上 Agent
        │
        ▼
③ 写提示词
   明确角色 + 任务 + 格式 + 约束
   temperature=0 先跑通
        │
        ▼
④ 建最小闭环
   一个脚本，输入 → 输出
   ⚠️ 先跑通，别管架构
        │
        ▼
⑤ 加数据/工具
   RAG 接文档，Agent 接工具
        │
        ▼
⑥ 建测试集
   50-100 题，有标准答案
   ⚠️ 没有它等于凭感觉调参
        │
        ▼
⑦ 迭代优化
   改一处 → 测一次 → 记数据
   ⚠️ 只改一个变量，别同时改
        │
        ▼
⑧ 加界面 + 部署
   Gradio/Streamlit → 上线
```

## 二、需求拆解流程（第 ① 步展开）

```
用户说："我想要个 AI 客服"
        │
        ▼
问清楚三件事：
  1. 它回答哪些问题？
  2. 答案从哪来？
  3. 答错了会怎样？
        │
        ▼
拆成具体任务
        │
        ├─▶ 意图识别
        │     分类 → temperature=0
        │
        ├─▶ 找答案
        │     检索 → RAG
        │
        ├─▶ 组织语言
        │     生成 → 提示词约束
        │
        └─▶ 兜底
              转人工 → 规则判断
        │
        ▼
逐个任务单独测
   （不要一次全上）
```

**核心原则**
> **一个模型调用只做一件事。**
> 又分类又检索又生成，效果一定差。

## 三、RAG 问答流程（在线，最核心）

```
用户提问
    │
    ▼
① 问题改写（可选但强烈建议）
   把口语问题改成检索友好的短句
   生成 3 个查询
    ⚠️ 提升命中率最划算的一步
    │
    ▼
② 向量化
   embedder.encode_one(query)
    ⚠️ 必须和建库用同一个模型
    │
    ▼
③ 检索 top-k
   store.search(vec, top_k=4)
    ⚠️ 记得归一化（点积=余弦）
    │
    ▼
④ 判断相关性
   最高分 < 阈值？
    │
    ├─ 是 ──▶ 直接回"根据现有资料
    │         无法回答"，不进模型
    │         （省钱 + 防编造）
    │
    └─ 否
         │
         ▼
⑤ 组装提示词
   资料 + 问题 + 三条约束
    ⚠️ 必须写"只依据资料回答"
    │
    ▼
⑥ 调用模型生成
   temperature=0.2
    │
    ▼
⑦ 拼接来源
   末尾附 [来源: 文件名]
    │
    ▼
⑧ 返回答案 + 来源
```

**⑦ 之后还可以做的事**
```
    │
    ▼
⑨ 记录日志
   问题/命中片段/分数/答案/token
    ⚠️ 这是后续优化的唯一依据
    │
    ▼
⑩ 人工反馈
   用户点赞/点踩 → 进测试集
```

## 四、RAG 离线索引流程（建库，只做一次）

```
文档目录 docs/
    │
    ▼
① 遍历文件
   rglob("*.md") / ("*.pdf")
    │
    ▼
② 读取
   txt/md → read_bytes().decode
   pdf    → pypdf 提取
    ⚠️ 编码错了会丢内容
    │
    ▼
③ 切块
   size=400  overlap=80
    ⚠️ 效果最大的一步
    │
    ▼
④ 批量算向量
   一次 64 条（省时间省钱）
    │
    ▼
⑤ 入库 + 存元数据
   text / vector /
   {source, index}
    │
    ▼
⑥ 持久化
   index.json
    ⚠️ 文档变了必须重建
```

## 五、RAG 效果不好 → 排查流程 ★

```
答案不对
    │
    ▼
先看检索到的片段（不是先看答案！）
    │
    ├─ 片段完全不相关
    │     │
    │     ▼
    │  ① 切块太大？
    │     把 size 从 1000 改成 300-400
    │  ② 没归一化？
    │  ③ embedding 不适合中文？
    │     换 bge-small-zh
    │  ④ 索引没重建？
    │
    ├─ 片段相关但答案不完整
    │     │
    │     ▼
    │  ① 加大 overlap（句子被切断）
    │  ② 提高 top-k（从 4 到 8）
    │  ③ 加 rerank
    │
    ├─ 检索不到但文档里确实有
    │     │
    │     ▼
    │  ① 加查询改写（最有效）
    │  ② 加混合检索（关键词兜底）
    │     专有名词/型号/代码靠这个
    │
    └─ 检索对但答案编造
          │
          ▼
       ① 强化提示词约束
       ② 加"资料不足就说不知道"
       ③ 建拒答测试集验证
          ⚠️ 这一步最后才做
```

**顺序不能乱：先查检索，最后才怀疑模型。**

## 六、Agent 工具调用流程

```
用户提问
    │
    ▼
① 把工具说明书 + 问题发给模型
    │
    ▼
② 模型返回什么？
    │
    ├─ 直接回答 ──▶ 结束，返回内容
    │
    └─ 请求调用工具
          │
          ▼
③ 把模型的 tool_calls 消息
   append 进 messages
    ⚠️ 最容易漏，漏了就报错
    │
    ▼
④ 解析参数
   json.loads(arguments)
    ⚠️ 必须包 try
    │
    ▼
⑤ 查注册表，执行真实函数
    │
    ├─ 工具报错 ──▶ 把错误信息
    │               作为结果回传
    │               （让模型换策略，
    │                 别返回空字符串）
    │
    └─ 成功
         │
         ▼
⑥ 把结果作为 role="tool" 回传
   带上对应的 tool_call_id
    │
    ▼
⑦ 步数 +1
    │
    ▼
⑧ 超过 max_steps 了吗？
    │
    ├─ 否 ──▶ 回到第 ② 步
    │
    └─ 是 ──▶ 强制结束，
              返回"已达最大步数"
```

**三条硬性保护**
```
① max_steps 上限
② 单次会话预算熔断
③ 同一工具连续调用 3 次强制退出
```

## 七、提示词迭代流程

```
① 写第一版
   角色 + 任务 + 格式 + 约束
        │
        ▼
② 用 10 个真实样例跑
   记录哪些对、哪些错
        │
        ▼
③ 找出错的类型
   是格式错？还是理解错？
        │
        ├─ 格式错 ──▶ 给出完整示例
        │             开 json_object
        │             加正则兜底
        │
        └─ 理解错 ──▶ 补充约束条款
                      给 1-2 个范例
        │
        ▼
④ 只改一个变量，重跑
   ⚠️ 同时改两处，不知道
      是哪一处起的作用
        │
        ▼
⑤ 变好了吗？
    ├─ 是 ──▶ 固化，扩大测试集
    └─ 否 ──▶ 回滚，试别的改法
        │
        ▼
⑥ 测试集扩到 50-100 题
   每次改动都全量跑一遍
```

## 八、批量处理流程（最易变现）

```
输入文件夹
    │
    ▼
① 遍历所有文件
    │
    ▼
② 线程池并发（2-4 起步）
   ⚠️ 并发太高会触发限流
    │
    ▼
③ 每个文件：
   读取 → 截断 → 提示词
   → 调模型 → 解析 JSON
    │
    ▼
④ 校验
   Pydantic model_validate
    │
    ├─ 失败 ──▶ 重试（最多 2 次）
    │           仍失败 → 记错误行
    │
    └─ 成功
         │
         ▼
⑤ 收集结果行
    │
    ▼
⑥ 全部完成后导出
   CSV（utf-8-sig，Excel 友好）
    │
    ▼
⑦ 统计报告
   成功率 / 失败率 / 总 token
   / 单份成本 / 平均耗时
```

## 九、上线前检查流程

```
能上线了吗？
    │
    ▼
① 超时设了吗？
   OpenAI(timeout=90)
    │
    ▼
② 重试做了吗？
   max_retries 或指数退避
    │
    ▼
③ 日志记了吗？
   每次调用写 jsonl
    │
    ▼
④ 密钥安全吗？
   .env + .gitignore
   仓库里没提交过？
    │
    ▼
⑤ 输出校验了吗？
   要进业务逻辑的必须校验
    │
    ▼
⑥ 成本可控吗？
   max_tokens 设上限
   有预算熔断
    │
    ▼
⑦ 工具安全吗？
   路径限制在项目内
   没有暴露 shell
    │
    ▼
⑧ 有测试集吗？
   50-100 题能一键跑
    │
    ▼
全打勾 ──▶ 可以上线
```

## 十、一张总表（打印用）

```
阶段        关键动作              判定标准
──────────┼────────────────────┼──────────────────
需求拆解   一模型只做一件事      任务能单独测
选方案     提示词>RAG>Agent      能用简单方案就别复杂
写提示词   角色+任务+格式+约束    10 个样例里对 8 个
建闭环     单脚本输入输出         能跑出结果
加数据     文档入库/工具注册       索引条数正确
建测试集   50-100 题有答案        能一键跑分
迭代       一次只改一个变量       分数上升
加界面     Gradio/Streamlit      手机能打开
上线       超时+重试+日志+校验    检查表全勾
```

## 十一、最高频的流程错误

**1. 跳过需求拆解直接写代码**
→ 写到一半发现方向错了

**2. 一个调用干三件事**
→ 分类+检索+生成混在一起，效果差还难调

**3. 先调模型，最后才看检索**
→ 检索错的东西，模型再强也救不回来

**4. 同时改提示词和切块大小**
→ 不知道哪个起的作用

**5. 没有测试集就上线**
→ 改一次坏一次，全靠运气

**6. 用原生 SDK 能写的东西硬上框架**
→ 出问题完全不知道框架内部在干什么
